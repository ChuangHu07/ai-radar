# AI Radar — 产品需求

2026-10-04 用户明确回复“不需要调整”，本需求及整体评审中的三项边界建议已批准。后续设计与技术细化列于 Open Questions；进入 4-spec。

## The Core Journey

2026-10-06 修订：首版前沿检索每批最多 5 篇；检索排序、异常逐篇确认和精读清单最多 10 篇的规则保持不变。

1. 每次打开程序都播放 AI Radar 名字艺术字动态开场，风格与前端的多维层叠视觉方向一致，持续约 1–3 秒；点击可以跳过并进入程序。
2. 进入资源获取模块首页：检索框下方提供两组入口——用户自定义分类标签索引，以及按 arXiv 官方分类投稿数量排序的大类标签；论文主题分类与 arXiv 保持一致。
3. 用户确定检索分类后，系统获取截至运行时、按 arXiv 首次投稿时间从新到旧排列的最新最多 5 篇论文；正常情况下直接生成前沿速览，全文获取或解析失败时先提示，由用户选择继续或移除失败论文后再生成。
4. 获取的论文送入 AI 阅读模块，以已确认的固定框架和精简、生动、形象的语言概括新进展。
5. 用户在速览中选择部分论文进入精读页面；也可以通过首页右上角的入口直接进入精读页面，上传自己的 PDF，无需先检索。
6. 在精读页面进一步确定资源：编辑删除论文，或通过上传 PDF 增加论文；检索论文与上传 PDF 使用同一份材料清单。
7. 材料就绪后，用户主动点击“生成报告”启动精读。最终清单一篇时进行单篇精读，多篇时进行联合精读，每次最多 10 篇；联合精读必须在最终清单中全部论文的全文获取和解析问题解决后才能开始。
8. 根据实际可获取、可解析的全文生成结果；获取或处理失败时报告原因。

依据：scope.md > The Core Loop、What “Working” Looks Like，以及用户本次对第一屏与两个模块的描述。

## Screens and Layout

### 开场

- 程序名 AI Radar 的动态艺术字，约 1–3 秒。
- 每次打开软件都播放，沿用前端已确定的多维层叠风格，以蓝紫色、层次与轻量动效保持视觉一致；具体动画形式在 UI 设计中完善。
- 用户点击可跳过并进入程序。
- 开场结束后进入资源获取首页。

### 资源获取模块

- 首页包含检索框。
- 首页右上角提供直接进入论文精读页面的入口；用户不必先进行分类检索。
- 检索框下方包含两组可区分的标签入口：自定义分类标签索引、分类投稿量排行。
- 自定义分类标签索引由用户选择关注的 arXiv 分类；首次打开时显示“待添加”，用户设置后关闭并重新打开程序仍保留。
- 分类投稿量排行采用 arXiv 官方提供的月度分类投稿统计，按该月投稿数量从高到低展示大类分类标签；展示前几名由后续 UI 设计根据可用空间确定。
- 主题分类与 arXiv 的分类对应，提供搜索检索功能。
- 获取论文并输送至 AI 阅读模块。
- 确定检索分类后，正常情况下直接生成前沿速览；全文失败时先按“速览生成前的异常确认”处理。用户可在速览中选择论文进入精读页面。

### AI 阅读模块

- 提供前沿速览和论文精读。
- AI 讲述支持中文、英语、中英双语三种输出语言。
- 从速览中快速选择、添加论文到精读材料。
- 提供用户自行上传 PDF 的入口。
- 单篇和多篇材料均可阅读；多篇一起分析精读。
- 论文精读使用独立页面，接收速览中选中的论文，也支持从首页右上角直接进入。
- 精读页面包含可编辑的材料清单：用户可删除其中的论文，或上传 PDF 增加论文，两种来源可以共同参与同一次精读。
- 精读页面提供“生成报告”按钮；材料就绪后等待用户主动点击，不自动开始精读。
- 资源获取与 AI 阅读为两个完整、独立的功能模块；前沿速览属于 AI 阅读能力，分类检索结束后直接向用户呈现速览。

## Look and Feel

- 希望通过程序名艺术字的动态开场提高整体软件的精致感。
- 速览语言非常精简、生动、形象。
- 用户明确选择 [多维层叠 / Dimensional Layering](https://vibeui.top/style.html?slug=uiuxpro-46-dimensional-layering&lang=zh) 作为应用整体风格，已查看实际预览。
- 采用浅灰蓝背景、深色文字、蓝紫渐变点缀、圆角卡片、多层阴影与轻量浮动感，体现深度和信息层次。英文参考 Inter 的现代无衬线观感；中文需在 macOS / Windows 上清晰显示。
- 风格应用于首页检索、分类入口、速览卡片与精读材料 / 报告区域；正文保持可读性，装饰性叠层不能遮挡内容。
- 每次打开软件播放开场，延续艺术字动态、1–3 秒与点击可跳过的要求；用户明确要求与前端风格相似，具体动效结合多维层叠方向在 UI 设计中确定。
- 参考核查和应用解释详见 visual-direction.md；现有 scope.html 的早期评审样式不代表当前应用设计。

## Features and Behavior

### 领域与分类检索

- 首版只接入 arXiv，获取最新最多 5 篇不同的相关论文，并保留来源与时间信息。
- 检索成功但结果只有 1–4 篇时，按实际获取数量生成前沿速览，显示实际篇数，不要求凑齐 5 篇。
- 检索成功但没有论文时，不生成或返回本次前沿速览报告，显示“未找到论文”的错误提示；不能用旧报告或生成内容充当本次检索结果。
- 检索接口或网络请求失败时报告实际失败原因，不将无法完成检索误报为“未找到论文”。
- 用户可搜索领域；分类与 arXiv 对齐。
- 首版同时支持自定义分类标签索引和分类投稿量排行；两组标签均可用于对应分类的检索。
- 自定义标签对应 arXiv 官方分类。
- 自定义分类标签区首次使用时没有已设置标签，显示“待添加”；该空状态只属于自定义标签区，月度投稿排行按自身数据状态展示。
- 用户设置的自定义分类标签在关闭并重新打开程序后保留；没有标签时继续显示“待添加”。具体添加 / 管理入口的布局在 UI 设计中完善。
- 排行标签按 arXiv 官方统计中的大类分组陈列，排序标准为官方给定月份的投稿数量，不使用访问量、下载量或第三方点赞作为标准。
- 统计粒度为官方月度数据，默认采用官方最新可用统计月并展示月份；该项已在整体评审中确认，不将查询当月无数据时的情况解释为零投稿。
- 排行数据尚未获取到或获取失败时，不显示月度排行区域；成功获取到可用数据后再展示，检索框和自定义标签仍可使用。
- 自动获取最多尝试 3 次，包含首次请求；显示本次自动尝试次数，例如“1/3”。成功即停止重试，连续 3 次失败后停止自动获取，不持续轮询或因页面重新显示而重新启动自动请求。
- 手动“获取排行”入口和尝试状态位于隐藏的排行区域之外，达到 3 次失败后仍可操作。用户主动点击才再次获取，成功后显示排行；失败时仍保持排行隐藏，不自行持续请求。具体重试间隔在技术规划中确定。
- 标签数量由后续 UI 设计根据可用空间确认，当前不指定前 3、前 5 或前 10。统计月份和投稿数量的展示方式也在 UI 设计中明确。大类统计分组与检索分类之间的对应在技术规划中核实。
- 官方统计页公开展示分类投稿数据，其公开源码包含按月份组织的大类数据；尚未实现统计读取和排行生成。详见 source-feasibility.md > 官方分类投稿量作为首版排行标准。
- 这项决定替代此前“首版只有自定义标签”的临时方案；第三方社区热榜留作扩展。

### 前沿速览

- 接收资源获取模块的论文，在 AI 阅读模块生成简明速览。
- 目标是提高研究者获取知识与筛选精读材料的效率，同时让该领域零基础的读者看懂论文在做什么；无需输入背景、已有了解或学习目标。
- 用户提出从大到小的“地址定位”讲述方式，用于解释论文在领域中的位置及具体贡献。
- 用户已确认前沿速览、单篇精读和联合精读的输出框架，并要求中文、英语、中英双语讲述。三套框架作为首版测试基线，整份 PRD 已获批准；后续根据测试微调并记录原因。

#### 前沿速览输出框架（已确认）

报告固定为“本批总览 + 按检索顺序排列的论文卡片”。首版检索目标为最新最多 5 篇；不足时有多少按多少生成，并显示实际数量，不用生成内容补齐。零篇时显示“未找到论文”，不生成报告。

**本批总览：这批论文在推进什么**

- 单语总览不超过 3 句，中文建议总计不超过 120 字；第一句用零基础读者能懂的话说明这批论文在处理什么麻烦，再介绍有依据的专业片区和不同进展。英语保持相当的信息密度与简洁程度，双语提供对应的两种表述。
- 使用“这批论文”的范围描述，不据 5 篇材料推断整个领域的全面趋势。
- 不强行归为一条趋势，也不自动决定联合精读论文簇。

**每篇论文卡片：用户 Prompt v2 分层卡片（第 2 步接入）**

2026-10-07 团队试读发现旧折叠态先呈现专业术语，对零基础读者不够友好。新版固定顺序为：通俗标题 → **先看懂**（2–3 句，场景、原来的麻烦、作者改变了哪一步与目的）→ 研究主题到具体贡献的专业定位 → **专业说法**一句话 → 研究贡献类型与精读建议。展开态仍为麻烦、妙招、效果、意义、冷静一下。先看懂约 60–110 字是软目标，不能为压字数删去必要条件；它不能把帮助理解的场景冒充已验证应用。专业层仍可使用术语，但要与通俗层讲同一件事。页面顶部先说这批论文在处理什么，再展示共同研究领域 / 子领域定位，按实际论文形成片区、关系和阅读顺序。少于五篇时按实际数量，不硬凑片区、相关工作或推荐名额。

2026-10-12 试读反馈希望图片帮助理解并增强速览表现力。逐篇卡片在标题与“先看懂”之间可展示与论文主题对应的概念插画：用视觉关系提示原来的难题、作者的做法或研究对象，旁边用短说明点明含义。插画必须明确标成“概念示意，非论文原图或实验结果”，不得承载未经来源核查的数字、效果或机制断言；原文依据和实际结果仍以文字与引用呈现。2026-10-13 团队指出第一版图太抽象，因此改为针对已核对五篇论文的具体场景图；没有对应且已核对的插画时不显示通用装饰图。图片在中文、英文界面均有替代文字与说明；窄屏先显示单个场景预览，读者可展开完整三步图。团队试读后再决定是否扩大主题库。

本文档采用输出设计，不自动采纳附带的按天 RSS、相关度重排、跨用户共享缓存或预生成服务建议。首版以当前时刻为截止获取 arXiv 最新最多五篇，保持首次投稿排序与全文失败等待用户选择的行为。第 2 步真实接入后再验收 S1–S4。

**随卡片保留的信息与操作**

- 论文原标题、arXiv 分类、首次投稿日期、来源链接及可用性状态；AI 生成的通俗描述不替换官方原标题。
- 标明实际阅读依据与覆盖范围（全文、部分正文或摘要），结果主张能对应来源位置。摘要层面的概括不能冒充全文阅读；材料不足时保留栏目并说明未提及 / 无法确认。
- 保留添加到精读的入口，由读者自行指定一篇或多篇。上传 PDF 的阅读入口和单篇 / 联合精读边界沿用已确定范围。
- 全文获取或解析失败时，生成报告前由用户选择继续或移除该篇；不得自动采用摘要回退。具体见下方异常确认。

#### 速览生成前的异常确认（已确认）

- 对前一问题中“全文不可用、摘要可用”的情况，用户要求在生成报告前提示，并询问继续生成或去掉这篇论文。
- 提示列出论文标题、全文获取 / 解析的实际失败原因，以及当前可用依据为摘要；用户作出选择前暂停报告生成，保留本批其他已获取的材料。
- **继续生成**：保留该篇，以当前可用摘要生成其速览，明确标注“仅基于摘要，全文未获取 / 解析成功”和失败原因；其他可用论文按各自实际阅读依据生成。不能编造正文细节或把摘要概括标为全文阅读。
- **去掉这一篇**：从本次速览的材料范围移除该篇，其余论文继续生成；报告标明实际纳入数量，不自动检索别的论文补足 5 篇，也不悄悄替用户跳过失败项。
- 多篇失败时，列出各篇及原因，确保每篇有明确处理选择；确认后按最终材料范围生成。本批总览只概括最终纳入且有依据的内容。
- 移除后没有可用材料时，不生成空报告，提示当前没有可生成速览的论文。
- 全文与摘要均不可用时，生成前列出失败论文及原因，用户可移除该篇或退出本次生成，不能选择无依据继续生成该篇；该边界在整体评审中已确认。
- 此处“继续生成”的摘要使用仅适用于前沿速览；进入精读后仍需可获取、可解析的正文，联合精读仍等待最终清单全部全文就绪。

#### 地址定位讲述示例（虚构，仅示范形式）

假设有一篇研究“让语言模型挑选更有用资料再回答问题”的论文；以下不是实际检索结果，也不含真实实验结论。

- **研究坐标**：计算机科学 → 人工智能 → 语言模型 → 查资料后回答问题 → 挑选有用资料。
- **在做什么**：像先查参考书再作答，资料太杂反而容易答偏。本文尝试让模型先挑出与问题有关的内容，再组织答案。
- **新进展**：把改进重点放在“给模型看哪些资料”；具体效果需要核对论文中的比较和实验结果。
- **用处与边界**：可能帮助文档问答更准确；能否推广到其他任务，需要相应证据。

“研究坐标”是解释性的定位路径，区别于 arXiv 官方分类字段，不要求跨学科研究具有唯一父子关系。卡片可用一句补充交叉方向，官方分类仍保留原值。

#### 前沿速览品控（已确认）

- 每次采用相同的报告层次、栏目名及栏目顺序，内容随论文变化；栏目不能因材料缺少而悄悄消失。
- 零基础读者只看标题与“先看懂”，就能回答：原来的麻烦是什么、作者做了什么、想解决什么；展开后还能回答研究推进、对谁有用及结论边界。
- 使用短句；首次出现的必要术语给通俗解释，避免未解释的缩写、宣传式评价和为生动而牺牲准确性的比喻。
- 类比用于辅助理解，不替代论文实际方法。不能把作者主张写成独立证实的事实，不能把潜在用途写成已实现能力。
- 获取 / 解析 / 生成失败时展示论文身份与实际失败原因，不写伪造的完整卡片；全文失败但摘要可用时，仅在用户明确选择继续后生成标明摘要依据的速览。
- 上述框架与品控已获确认，构建验收需检查结构、语言可理解性、来源依据和篇幅目标；具体模型和实现方式留到技术方案。

### 界面语言与报告语言

- 用户已明确：应用界面允许中文 / English 切换；生成的报告支持中文、英语、中英双语三种语言。
- 首次打开时，界面语言与报告语言均默认中文；两项分别记住用户上次的选择，下次打开恢复各自设置，不强制两者一致。
- 界面语言覆盖导航、按钮、栏目标签、操作提示及状态 / 失败原因的说明；论文原标题、arXiv 分类标识和来源链接保留原值。
- 界面语言和报告语言分别选择。例如英文界面也可以生成中文或中英双语报告；切换界面语言不自动改变报告的语言选择或已生成内容。
- 三种报告语言覆盖前沿速览、单篇精读和联合精读，沿用已经确认的输出框架与品控标准。
- 三种语言保持同一套内容结构和栏目顺序；语言选择不改变检索范围、论文选择、研究坐标、结论或证据。
- 中文使用简明中文；英语使用同样适合该领域零基础读者的简明英语，必要术语首次出现需解释。
- 中英双语按栏目对应提供中文和英文，以便对照理解。具体排版留到 UI 设计；两种表述中的数字、条件、结论边界、来源及缺失信息应一致。
- 论文原标题与来源链接始终保留原值；通俗讲述及栏目标题按所选语言呈现。
- 已生成报告后，用户切换报告语言即直接触发对应语言的报告生成，无需再次点击“生成报告”或确认；覆盖前沿速览、单篇精读和联合精读。
- 语言切换沿用该报告对应的同一批论文、材料范围、阅读依据和固定框架，不重新检索或改选论文；保持事实、数字、条件与引用一致。这里是生成相应语言版本，不承诺无需等待的即时显示。
- 生成期间显示目标语言和正在生成的状态，成功后展示对应版本；失败时报告原因，并提供“重新生成”和“退出”，沿用下方报告生成失败恢复规则。
- 精读尚无报告时仍由用户点击“生成报告”首次启动；选择语言本身不代替首次启动，也不绕过材料就绪检查。
- 默认值与选择保留方式已确认；选择控件布局留到 UI 设计。界面语言切换本身不触发报告生成。

### 统一精读材料

- 从速览选择的论文与上传 PDF 均作为阅读材料，沿用同一套单篇 / 多篇阅读操作。
- 单篇精读和最多 10 篇的联合精读分别使用固定输出形式。
- 阅读依据为可获取整篇论文或上传 PDF 中实际解析的正文。
- 论文来源标识应保留；上传 PDF 不应被误标为 arXiv 检索结果。
- 从速览带入的材料为用户选中的论文，不自动将其余检索结果加入精读任务。
- 在精读页面，用户可主动删除论文，并通过上传 PDF 增加论文；当前清单统一管理两种来源。
- 编辑后的最终清单决定精读范围：一篇单读、2–10 篇联合精读。清单为空时没有可开始的精读任务。
- 添加材料将超过 10 篇时，拒绝本次超限添加，保留原清单，提示“每次精读最多 10 篇”；用户可移除已有材料或减少本次添加数量后再添加，不自动挑选、截断或删除论文。

### 精读报告启动（已确认）

- 用户明确要求精读页面有“生成报告”按钮，由用户主动点击启动精读；添加、删除、上传完成或材料全部就绪均不自动生成报告。
- 按钮以当前材料清单的就绪状态为依据：清单为空、超出 10 篇或存在全文获取 / 解析问题时不可启动，并显示具体阻塞原因；1–10 篇材料全部就绪后可用，用户仍可继续编辑清单。
- 点击时按最终清单确定单篇 / 联合精读，并采用所选报告语言及对应固定框架。
- 开始后显示正在生成的状态，避免重复点击启动同一任务；生成成功后展示报告，失败时显示实际原因，提供“重新生成”和“退出”。

### 报告生成失败恢复（已确认）

- AI 报告生成失败时，显示实际失败原因，提供“重新生成”和“退出”两个操作，适用于前沿速览、单篇 / 联合精读及报告语言切换生成。
- **重新生成**：由用户主动触发，沿用本次已确认的材料范围、报告语言和固定框架；不要求重新上传已就绪材料，不重新检索或自动改变论文清单。显示生成状态，避免重复启动；再次失败时仍可看到原因和两个操作。
- 精读重试仍须满足当前任务的全文就绪与数量条件，不绕过材料检查；不会把失败结果标成完整报告。
- **退出**：退出本次失败的报告生成流程，不继续重试；保留当前页面供用户调整材料或重新检索。此解释已在整体评审中确认。
- 不因退出而自动移除论文；退出后的跨会话材料或报告保存尚未确定，自定义分类标签保留规则不受影响。

### 精读失败材料恢复（已确认）

- 全文获取或 PDF 解析失败时，在对应论文旁显示实际失败原因，提供“重新上传 PDF”和“移除这篇”两个操作。
- 重新上传用于替换该条目的失败材料，不额外增加论文数量；对新 PDF 再次检查正文解析结果，成功后该篇才进入就绪状态。正文实际来源标明为用户上传，不能标成已从 arXiv 成功获取。
- 重新上传后仍无法解析时，保留失败状态与最新原因，用户可再次上传或移除；上传完成本身不等于材料就绪。
- 移除由用户主动执行，只改变当前精读任务的材料范围，其他已就绪论文保留。
- 每次替换或移除后重新检查最终清单：剩余一篇为单篇精读，2–10 篇为联合精读，空清单无法生成；任意剩余材料未就绪时仍无法启动。
- 全部就绪后仍等待用户点击“生成报告”。这两项操作解决材料获取 / 解析问题；AI 报告生成失败时通过“重新生成”或“退出”处理。

### 联合精读启动条件（已确认）

- 用户明确要求：解决所有无法获取的论文后，才能开始联合精读。
- 对精读页面编辑后的最终材料清单检查全文可获取、可解析状态，统一适用于 arXiv 论文和上传 PDF。只有清单中全部材料就绪且数量在 2–10 篇范围内，联合精读才能开始。
- 任意一篇全文获取或解析失败时，先显示该论文和实际失败原因，任务处于等待问题解决状态。
- 不自动跳过失败论文，不以摘要替代其全文，不在缺少材料时先生成部分联合报告。
- 用户主动删除论文属于重新确定精读范围，启动检查以编辑后的最终清单为准；系统不能代替用户删除失败项来通过检查。
- 已就绪材料保留在本次任务中；所有失败材料修复并检查通过后，“生成报告”按钮才可用，仍等待用户主动点击，不自动开始生成。
- 失败材料通过对应论文旁的“重新上传 PDF”或“移除这篇”处理；上传后必须重新验证正文解析，不能把“报告失败原因”或上传完成当作问题已经解决。

### 单篇精读框架（用户 Prompt v2，2026-10-04）

用户在熟悉论文的实际试用后反馈质量不足，明确要求采用所提供的四份 Prompt 文档。新单篇报告按认知顺序组织，不再沿用六栏摘要式正文；操作流程、完整正文要求、三种报告语言和双系统运行边界保持。

| 顺序 | 部分 | 固定学习目标 |
| --- | --- | --- |
| ① | 30 秒速读卡 | 一句话、由大到小的研究定位、核心结果、直接表达的研究贡献类型及可检验的学习收获 |
| ② | 研究定位与具体贡献 | 研究领域→子领域→具体主题→关键问题或技术路线→本文方案与贡献，每层包含问题链；相关工作与区别、研究问题与缺口、研究贡献类型 |
| ③ | 读之前先备好 | L0–L3 知识地图、够用标准、自检题与依赖；按基础给三条阅读路线 |
| ④ | 核心思想 | 一句话、机制类比、技术表述；比喻明确对应部件和边界 |
| ⑤ | 方法拆解 | 数据流、部件做什么及为什么、设计追问、新概念卡和伪代码 |
| ⑥ | 公式精讲 | 问题、符号、逐项解释、直觉检验、手算小例子；没有核心公式时隐藏 |
| ⑦ | 实验怎么读 | 主张与证据对照、主表解读、证据强度、追问、复现条件 |
| ⑧ | 有什么用 | 学术价值、工程应用、作者局限及标注的 AI 分析 |
| ⑨ | 检验一下 | 分层自测、参考答案和费曼挑战 |
| ⑩ | 接下来读什么 | 真实前作、相邻路线、未来方向的检索关键词及术语表 |

一次生成一份分层内容，读者可选路线、跳过已会概念和展开技术版，不要求填写背景。背景知识、作者主张、【AI解读】和【教学示例】明确区分。资源推荐不给模型自造链接；未接入已验证资源库时显示名称和关键词。上传 PDF 保留物理页定位；不能凭空生成 arXiv HTML 章节链接或声称 PDF 转写等于原始 LaTeX。

四份原始设计文档见 prompt-design/，共享规则 R1–R6、独立审校 E1–E8 作为 v2 质量基线。当前先验证中文单篇；英语 / 双语仍按原第 5 步实现。联合模板继续原已确认六栏，后续沿用分层讲解和相同事实纪律，不擅自将单篇十部分复制成多篇报告。

### 联合精读框架（已确认测试基线）

目标：基于用户自行指定的 2–10 篇论文，解释它们在共同问题上的不同路线、证据、相互关系与可学知识；不会自动选择论文簇。

| 固定栏目 | 内容 |
| --- | --- |
| 共同研究范围 | 用地址定位说明这组论文讨论的范围，列出每篇的具体切入点；无充分共同问题时如实说明 |
| 共同知识与概念差异 | 共同基础集中解释一次，指出不同论文中相似术语是否实际指向不同定义或条件 |
| 研究路线对照 | 用表格比较每篇的问题、做法和关键区别，说明它们分别改变哪一步，而非逐篇精读报告的拼接 |
| 证据与结果对照 | 保留各自的验证条件与来源；不同数据、任务、指标或条件不能直接比较时明确注明，不编造统一名次 |
| 互补、分歧与边界 | 解释哪些方法互补、结论是否有分歧及其依据；不能仅凭时间顺序宣称一篇改进了另一篇，或把跨论文推断写成作者原结论 |
| 联合知识收获 | 组织概念与方法之间的关系，提炼这组论文共同说明了什么、哪些问题仍缺少证据；不延伸成已延期的研究设计建议 |

联合报告按实际材料量调整解释深度，共同背景不重复讲十次。用户选择的每篇论文都需在材料清单及对照中可识别；全文获取或解析失败时按已确认的启动条件等待全部问题解决，不能继续生成部分联合结果。

### 精读品控（已确认测试基线）

- 精读依据为实际可获取或解析的正文，显示材料及阅读覆盖范围。仅有摘要时不能输出标为全文精读的报告。
- 核心主张与关键数字标注来源；优先定位到 PDF 页码或论文章节，PDF 文件页码与印刷页码应区分。无法可靠定位时说明，不能编造页码。
- 固定栏目和顺序保持一致；论文未涉及或材料无法支持时，在相应栏目明确标注。
- 通俗解释能帮助读者理解方法，但不改变技术含义；必要术语、公式和条件有说明。
- 联合精读能追溯每篇的贡献与证据，明确“可比较 / 不可直接比较”；作者结论、跨论文综合及分析判断分开表述。
- 三种讲述语言执行相同标准，双语事实、数字、条件、引用一致。
- 2026-10-04 用户提供 Prompt 并要求重新修改生成质量，单篇改为 v2 分层导读；联合框架与操作边界保持。审校发现严重事实、公式或算术错误时不发布，最多两轮定点修订后仍不通过则报告质量失败。
- 同一模板版本保持栏目与讲述标准一致；测试中调整框架时同步更新本需求文档，并记录调整及原因，避免各次运行任意改变结构。

## Acceptance Criteria

- [ ] 进入资源获取首页，能够看到检索框及其下方两组入口：自定义分类标签索引、分类投稿量排行。
- [ ] 用户能够自定义选择分类，并通过标签进入对应分类检索。
- [ ] 首次打开时，自定义分类标签区显示“待添加”；设置标签后关闭并重新打开程序，仍能看到已设置标签并用于分类检索。
- [ ] 排行使用 arXiv 官方月度分类投稿数量，按该月数量降序显示大类标签；实际标签数量与后续确认的 UI 布局一致。
- [ ] 排行未获取到时隐藏该区域，其他首页入口可用；自动请求最多 3 次（含首次）并显示尝试次数，连续失败后停止，只有用户主动点击外部“获取排行”入口才再次请求，成功后显示排行。
- [ ] 分类能对应 arXiv 分类；搜索后展示最新论文、来源链接和时间依据。
- [ ] 检索成功返回 1–9 篇时，按实际数量生成前沿速览并显示篇数；返回零篇时显示“未找到论文”，不生成本次报告。接口 / 网络失败显示实际原因，与零结果区分。
- [ ] 检索取得的论文能进入阅读模块并生成前沿速览。
- [ ] 确定检索分类后，正常情况下直接生成前沿速览；用户在速览中选中的论文可带入独立的精读页面。
- [ ] 全文失败但摘要可用时，报告生成前显示论文、失败原因和摘要依据，等待用户选择继续或移除；继续时明确标注摘要速览，移除时按剩余材料生成并显示实际数量，不自动补齐或跳过。
- [ ] 首页右上角可直接进入精读页面，无需先进行分类检索即可上传 PDF。
- [ ] 精读页面能删除已添加论文、通过上传增加论文，并将检索论文和上传 PDF 共同作为本次任务材料；模式与就绪检查以最终清单为准。
- [ ] 精读通过用户点击“生成报告”启动；材料就绪不会自动生成，空清单、超出数量或全文未就绪时无法启动且可看到原因，生成期间显示状态并防止重复启动。
- [ ] 前沿速览采用已确认的“本批总览 + 逐篇卡片”；每篇先显示“先看懂”的具体麻烦与做法，再给研究定位和专业说法，展开后保留新进展、用处与边界；符合简明、零基础可理解和来源可追溯的标准。
- [ ] AI 讲述可选择中文、英语或中英双语；各语言沿用对应模式的固定结构，双语表述的事实、数字、条件与来源一致。
- [ ] 应用界面可切换中文 / English，导航、按钮、操作提示及状态 / 失败原因说明使用所选界面语言；论文原标题、分类标识和链接保留原值。
- [ ] 报告语言可独立于界面语言选择；英文界面能生成中文或中英双语报告，切换界面语言不自动更改已有报告内容。

- [ ] 精读失败论文旁可重新上传 PDF 或移除；重新上传替换该条材料且须解析成功才就绪，移除后按剩余清单重新确定单篇 / 联合精读及按钮状态，其他就绪材料保留。
- [ ] 全文和摘要均不可用时不能无依据生成该篇速览，可移除或退出；超限添加被拒绝，原精读清单保留并显示最多 10 篇的提示。
- [ ] 单篇精读使用用户 Prompt v2 的十部分学习路径（无核心公式时九部分）；前置知识可自检、核心思想分层、关键主张可追溯，公式和教学例子经过独立审校。
- [ ] 联合精读包含已确认的六栏：共同研究范围、共同知识与概念差异、研究路线对照、证据与结果对照、互补 / 分歧与边界、联合知识收获；每篇材料可识别，结论保留验证条件与来源。
- [ ] 获取或处理失败能够看到实际原因，缺少全文时不把摘要讲解标为全文精读。
- [ ] Windows 本地运行与完整旅程验证，结果在构建阶段记录；macOS 实机为可选补充，不阻挡完成。
- [ ] 页面体现已确定的多维层叠视觉方向：浅色底面、蓝紫点缀、卡片阴影和清楚的层次；论文正文与失败原因可读，中文 / 英语 / 双语均不被装饰遮挡。

## States and Boundaries

- 每次打开软件都播放开场，约 1–3 秒，点击可跳过；开场结束或跳过后进入首页。
- 首次使用时自定义分类标签区显示“待添加”；已设置的分类标签在下次打开时保留，空状态不影响月度排行入口。
- 首次使用界面及报告均默认中文；后续打开分别恢复各自上次的语言选择，语言设置保留不意味着已经保存或重新生成历史报告。
- 月度排行失败时隐藏该区域；自动尝试最多 3 次，成功停止，3 次失败停止自动获取，保留外部手动获取入口及尝试状态。
- 获取、上传解析和 AI 生成失败时报告原因；精读材料失败可重新上传或移除，报告生成失败可重新生成或退出。具体提示样式在 UI 设计中完善。
- 速览全文失败但摘要可用时，在报告生成前等待用户选择继续或移除；全文和摘要均不可用时不生成该篇的讲述，可移除或退出本次生成。
- 精读中部分正文不可用或上传 PDF 无可读取正文时，显示逐篇原因，支持重新上传或移除；联合精读须等待最终清单全部材料就绪。只剩一篇仍需其正文就绪，清单为空则无法生成。
- 检索成功但不足 5 篇时，按实际数量生成速览；零篇时不返回报告，显示“未找到论文”。请求失败显示实际原因，不能当作零结果。
- 来源材料的数量上限为 10 篇，超限添加被拒绝并保留原清单；文件大小、页数与解析能力边界在技术规划中确定。

## Product Decisions

- 两个模块：资源获取和 AI 阅读；用户希望程序功能完整且相互独立。
- 单一检索来源：arXiv；其他接口以后补充。
- 2026-10-04 原检索数量边界：不足 10 篇时有多少按多少生成前沿速览；没有结果时不返回报告，提供“未找到论文”错误提示。2026-10-06 首版检索目标改为最多 5 篇，零结果规则不变。
- 搜索首页：检索框，下方同时提供自定义分类标签索引和分类投稿量排行；分类与 arXiv 一致。
- 2026-10-04 自定义标签首次显示“待添加”，用户设置后下次打开仍保留。
- 最新排行标准：用户明确选择 arXiv 官方月度分类投稿数量，按统计分组陈列大类；此前仅采用自定义标签的临时方案被替代。前几名由后续 UI 设计根据可用空间确认。
- 2026-10-04 排行异常：暂不可用时隐藏区域，获取到才显示；自动获取总计最多 3 次，全部失败后停止，除非用户主动点击获取。尝试次数和手动入口放在隐藏区域之外。
- 动态开场：程序名艺术字、约 1–3 秒、点击可跳过，用于提高精致感；2026-10-04 用户明确每次打开软件播放，风格与前端相似。
- 材料入口统一：检索结果与上传 PDF 同等参与精读，一篇单读、多篇联合分析。
- 页面衔接已确认：分类确定后直接生成速览；选中论文进入精读页面，首页右上角也可直接进入；精读页支持删除论文和上传补充材料。
- 应用视觉风格已确定为用户提供的多维层叠参考，核查记录见 visual-direction.md；细节布局后续设计。
- 速览框架已确认：本批总览 + 每篇固定 4 栏（研究坐标、在做什么、新进展、用处与边界）；研究坐标采用从大到小的地址定位思路，兼顾研究者效率与零基础可理解性。
- AI 讲述语言支持中文、英语、中英双语，固定结构和品控在各语言下保持一致。
- 2026-10-04 用户明确补充：界面支持中文 / English 切换，报告仍支持三种语言；两类语言分别控制。
- 2026-10-04 用户明确界面与报告语言首次默认中文，并记住上次选择；两项设置分别保留。
- 2026-10-04 用户明确生成后“直接切换生成”：更换报告语言即生成对应版本，沿用同一批材料和固定框架，无需另行确认；界面切换不触发此操作。
- 单篇精读与联合精读框架已确认，先作为首版基线使用，后续通过测试微调并同步文档。
- 联合精读启动条件：所有所选论文的全文获取 / 解析问题解决后才能开始，不能自动跳过失败材料或先生成部分联合结果。
- 2026-10-04 精读主动启动：材料就绪后，由用户点击精读页面的“生成报告”按钮开始，不自动生成。
- 2026-10-04 精读材料恢复：获取 / 解析失败的论文可重新上传 PDF 或由用户移除；重新检查最终清单后判断是否允许生成，不改变全部全文就绪要求。
- 2026-10-04 用户明确 AI 报告生成失败后“重新生成或者退出”；整体评审确认退出结束本次生成流程并保留当前页面。
- 2026-10-04 速览异常确认：生成报告前提示全文失败论文及原因，由用户选择继续生成或去掉该篇；承接摘要可用的情境，继续时明确标注摘要依据，不改变精读全文要求。
- Markdown 优先迭代，稳定后生成带流程图的 HTML 评审页，修改同步回 Markdown。
- 2026-10-04 用户明确“不需要调整，请你继续下一步，你可以先起一个大纲”，批准整份产品需求及三项边界建议；3-prd 完成，开始 4-spec 技术大纲。
